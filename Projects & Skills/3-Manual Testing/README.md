# Manual Testing

Manual Testing is a software testing approach where testers manually execute test cases without relying on automated test scripts. The goal is to verify that the system behaves as expected, identify defects, and ensure that the software meets its requirements.

This section contains documentation and templates covering the main activities of the manual testing process, from test planning and test execution to defect reporting and test result summary.

### Available Documents

| # | Document                  | Description                                                                                                   |
| - | ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 1 | **Test Plan**             | Defines the testing scope, objectives, strategy, resources, schedule, and overall test approach.              |
| 2 | **Test Scenario**         | Defines high-level scenarios and user flows that need to be tested.                                           |
| 3 | **Test Case & Execution** | Defines detailed test steps, test data, expected results, and records the actual test results.                |
| 4 | **Test Progress Report**  | Tracks testing progress, including executed test cases, Pass/Fail status, and defects found during testing.   |
| 5 | **Bug Debug Report**      | Documents identified bugs, including steps to reproduce, expected vs. actual results, severity, and priority. |
| 6 | **Regression Test**       | Verifies that existing functionality still works correctly after bug fixes or system changes.                 |
| 7 | **Test Summary Report**   | Summarizes the overall testing results, including test execution status, defects, and final test status.      |
